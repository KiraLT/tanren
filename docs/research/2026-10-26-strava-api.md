# Strava API for a one-way export (ADR-0018 input) — 2026-10-26

**Question.** OAuth, manual activity create/update/delete, rate limits, app registration, API terms, Apple Health bridge, webhooks: what holds for Tanren pushing gym sessions to Strava from the Worker?
**Setup.** WebFetch of developers.strava.com and strava.com/legal pages; `curl` of /docs/reference, /legal/api and /legal/api_policy, then grep of the text (all fetched 2026-10-26).

## Answers
1. **OAuth (verified).** `GET https://www.strava.com/oauth/authorize?client_id&redirect_uri&response_type=code&approval_prompt=auto|force&scope&state` (the mobile variant is `/oauth/mobile/authorize`). Scopes are comma-separated. Create needs `activity:write` ("access to create manual activities and uploads"). Updating "Only Me" activities also needs `activity:read_all`. Token: `POST https://www.strava.com/oauth/token` with `client_id, client_secret, code, grant_type=authorization_code`. It returns `access_token, expires_at, expires_in, refresh_token, athlete, scope`. Check `scope`, because the user can untick scopes. Refresh uses the same URL with `grant_type=refresh_token, refresh_token`. "Access tokens expire six hours after they are created." The refresh token **rotates**: "Once a new refresh token is returned, the older refresh token is invalidated immediately." The `redirect_uri` "must be within the callback domain"; localhost is allowed. Revoke: `POST https://www.strava.com/oauth/revoke` with Basic auth (client_id:client_secret) and `token`. The legacy `/oauth/deauthorize` is removed on 2027-06-01. A web redirect to api.tanren.me needs no deep link. The Strava-app handoff (iOS `LSApplicationQueriesSchemes: strava`) is optional.
2. **Create (verified).** `POST /api/v3/activities` (form) requires `name, sport_type, start_date_local (ISO 8601), elapsed_time (s)`. Optional: `description, distance (m), trainer (1), commute (1), tags[...]`, and the deprecated `type`. `WeightTraining` is in the SportType enum (so are `Workout`, `Crossfit`, `HighIntensityIntervalTraining` and `Yoga`). **Update:** `PUT /api/v3/activities/{id}`. The UpdatableActivity body is only `name, description, sport_type, commute, trainer, hide_from_home, gear_id, tags`, so start time and duration **cannot** be changed. **Delete: no endpoint.** The reference has only get/post/put verbs, so the athlete deletes on strava.com. **Duplicates:** POST /activities has no idempotency key or dedupe in the docs (UNVERIFIED). File uploads (`POST /uploads`, `external_id`) do run a duplicate check ("duplicate of activity N"). **Feed:** the docs say nothing about whether a manual activity without GPS/HR appears in the feed normally (inferred yes: manual entries show in the feed as cards with no map).
3. **Limits and registration (verified).** Overall: 200 requests per 15 min and 2,000 per day. Read (non-upload) requests: 100 per 15 min and 1,000 per day. POST activities and uploads are excluded from the read bucket. Windows reset at :00/:15/:30/:45 and daily at 00:00 UTC. Over the limit returns HTTP 429. Headers: `X-RateLimit-*` and `X-ReadRateLimit-*`. New apps start in "Single Player Mode" (athlete capacity 1, the developer only), upgradeable to 10. Registration: strava.com/settings/api gives Client ID, Client Secret and a 6-hour token. Set "Authorization Callback Domain" to a real domain when live (here `api.tanren.me`; it is a host, not a URL). **"A Strava subscription is a prerequisite for creating an app."** (API Policy 3.3, effective 2026-06-01.)
4. **Terms (verified, API Agreement + API Policy, effective 2026-06-01).** Strava Data goes "only… to that user". Users' deletions must be reflected "within forty-eight (48) hours" (6.3). Delete all data on user request or revoke, with written confirmation (2.5). §5.3 forbids using Strava Data "in connection with the… operation of any AI Application", including "ingestion into a context window". "Strava Data" means data you access or collect *from* the Strava API. 5.4 bans combining Strava Data with other data for analytics. The app name must not contain "Strava". The connect button links to `/oauth/authorize`, 48 px @1x. Links to activities read "View on Strava" (bold, underline or #FC5200). Do not modify the logos or imply Strava sponsors the app.
5. **Apple Health (UNVERIFIED, leaning no).** The support article says Strava will "automatically send Strava activities to Apple Health" (type, distance, time, calories). It also says routes "from activities recorded with an app from another company" are not sent, and it says nothing about API-created manual activities. A TrainerRoad forum user reports that third-party activities synced to Strava no longer reach Health. Write HealthKit directly instead (needs a dev build).
6. **Webhooks (verified, note only).** `POST /api/v3/push_subscriptions` (`client_id, client_secret, callback_url, verify_token`). There is one subscription per app. The endpoint must answer the GET `hub.challenge` echo. Events carry `object_type` (activity/athlete), `aspect_type` (create/update/delete), `updates` (title/type/private, or `authorized:"false"` on deauth) and `owner_id`, and need a 200 within 2 s. Deauth/delete events are the practical way to meet 6.3 and 2.5.

## What it means for Tanren
- Store `stravaActivityId` per session, because there is no dedupe and no delete. Edits can push only name, description and sport_type. Use `sport_type=WeightTraining` with `trainer=1`.
- Store the rotated refresh token on every refresh (D1, per user). Refresh when `expires_at` is less than 1 h away.
- **Never pull Strava responses into D1 data the MCP exposes to Claude** (§5.3). Keep only the opaque activity id, and drop it on revoke.
- Owner actions: a Strava subscription, an app at strava.com/settings/api with callback domain `api.tanren.me`, and Worker secrets `STRAVA_CLIENT_ID`/`STRAVA_CLIENT_SECRET`. Single Player Mode (1 athlete) is enough.
