## Top wastes
1. **Unbounded runs and research for later steps burned the budget and ended session 1 at about 60%.** S1-R0 30m, S1-T0 34m (sample matrix), S1-T9 19m (40-test workbench), S1-A 37m, plus 4 researchers for steps 2–7. Six agents ran at once, hit the rate limit and all died. Compare S2 with time boxes: T4 took 2m30s, the review 1m44s, a fix round 1m42s, at about 70–85k tokens each against 220–350k. Root cause: briefs had no time box or bar, and nothing capped concurrency. The playbook fixed this, but **only in lead-playbook**. The agent files and the brief template still carry no time box, so the next brief written in a hurry will leave it out again.
2. **The architect sat on the critical path for 37m.** It spawned its own researcher, waited on it, needed 2 nudges, and wrote an 893-line design for a schema package. S1-R0 was serialized about 20m ahead of it. Engineers needed only §4–§10. Root cause: architect.md has no time box or size cap, and it says "write the question down for a researcher", which in practice became "wait for one". The Lead then also composed briefs from the design (step-1-briefs.md), which adds another hop.
3. **Stale pipeline definitions plus a conflicting test bar.** dev-system.md §3 and the build-step skill still require research → architect → … → QA, which contradicts the playbook's short pipeline. The handoff told session 2 to run T6 and QA, and the Lead had to cut them by hand. The new bar, "a few targeted tests", contradicts `.claude/rules/tests.md` ("round-trip for every schema"). As a result T5 shipped without round-trips and the review's one blocking finding cost a full fix + re-check round (≈ 10 min).

## Proposed changes
1. **lead-playbook · Brief template**: after the `Role:` line insert `Time box: <10–15> min (at the box: stop, report what you have + gate output + what is left) · Report ≤ 40 lines`. Replace `- [ ] tests: <what must be covered>` with `- [ ] tests per .claude/rules/tests.md: every exported Schema has decode-ok, decode-fail (path asserted), round-trip; plus <task-specific>`.
2. **lead-playbook · Cost discipline, bullet 1**: replace `*compiles, gate green, a few targeted tests*` with `*compiles, gate green, exactly the tests .claude/rules/tests.md requires*`.
3. **lead-playbook · Observe and improve, "Log metrics"**: replace the format with `HH:MM→HH:MM · task · role/model · duration · tokens · tool uses · rounds · outcome`. Add: `On every returned report: first dispatch dependents and route fixes, then write the Log and status (bookkeeping is never on the critical path).`
4. **architect.md · new section `## Time box` before `## Outputs`**: `Deliver within the brief's time box (default 15 min). Never spawn or wait on a researcher: mark unknowns "VERIFY: <question>" and continue; the Lead dispatches research in parallel. Design notes ≤ 300 lines, only contracts the step's engineers need. Output 3 is written as ready-to-paste briefs (lead-playbook template) in docs/tasks/step-N-briefs.md.`
5. **engineer.md · item 6**: replace it with `Formatting runs only on Write/Edit (hook). Write source files with Write/Edit, never Bash heredocs; if you did, run pnpm format before the gate.` Add item 9: `Respect the brief's time box (default 15 min). At the box, report what you have with gate output and a list of what is left; do not polish beyond the done-criteria.`
6. **researcher.md · append**: `Time box: the brief's (default 10 min), ≤ 4 questions per dispatch, report ≤ 40 lines. Only research the step being built. Code snippets are "unverified" unless you compiled them.`
7. **build-step SKILL · step 8**: replace it with `**QA only if the step touches ≥ 2 packages or the diff > ~800 lines.** Otherwise the reviewer runs pnpm check and that output is the gate evidence.` **dev-system.md §3 diagram**: change `├─► Researcher (only if …)` to `├─► Researcher ∥ Architect (research never ahead of design)` and the QA box to `QA (big steps only; small steps: reviewer runs the gate)`.
