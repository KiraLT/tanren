Measured on TOOL-1 (engineer/sonnet, 2026-10-20 22:51, first agent after the all-tools + disallowedTools switch) and the step 4 ∥ 7 transcripts:

- Subagents get 10 direct tools (Artifact, Bash, Edit, Read, Skill, ToolSearch, Write, SubagentHandback, advisor, placeholder); every MCP tool (context7, cloudflare docs, Claude Docs) and WebFetch is deferred behind `ToolSearch`. `Skill` is direct; plan-web engineers loaded `expo:expo-router`, `frontend-design`, `ui-check` via Skill. context7: still 0 engineer calls through step 4/7; only fable architects use it.
- `maxTurns` counts API turns, not tool calls: ≈ 7 turns/min on sonnet, ≈ 6 on opus; 120 covers a 15–20-min box.
- Role-file edits are read once, at spawn: an agent dispatched 2 min after an edit still had the old text (TOOL-1); a team-lead spawned 23:45:24 ran its whole 17+ min on the 23:38 team-lead.md while the 23:52 rules landed. Count a role-file failure only when the agent started ≥ ~5 min after the edit; forward deltas to live agents by message.
- Metrics source: `<session scratch>/tasks/<agentId>.output` (jsonl; nested team agents included). Per agent: span = first→last `timestamp`; active = sum of (user message that is not a tool_result → next SubagentHandback); turns = distinct assistant `message.id`; tool uses = `tool_use` blocks; tokens = `message.usage` deduped per message id. **Timestamps are UTC; the Log is Europe/Vilnius (UTC+3 in October).** The Lead's remembered times were 2–8 min off (fan-out "23:14" = 23:16:44). Hand counts in the Log undercount tool uses ~2×.
- Resume mechanics: a team-lead resumes a finished engineer with `SendMessage(to: <id>)` (result "Resuming agent …"); the engineer's reply arrives as "Another Claude session sent a message" and wakes the team-lead. A `[handback-send-enforce]` nudge fires when an agent ends a turn without SubagentHandback; 9 agents got it in step 4/7, and it produced the mcp team-lead's premature report (23:42:55 idle turn end → 23:43:18 hand-back with a fix child in flight). Waiting = Monitor or a Bash until-loop on the child's transcript (the resumed mcp team-lead did this, 79-s Bash call).
- Foreground `Agent` calls serialize a team-lead's turn: two in one message (P6 + REV at 23:34) meant the REQUEST CHANGES result (23:36:31) was acted on only when P6 returned (23:41:23). Children must be `run_in_background: true`.
- Lead latency pattern: dependent dispatch < 1 min while ≥ 2 streams ran (step 2); 8.2 + 5.7 min at a single-agent tail (step 2); 16-min dispatch gap right after a two-team fan-out (step 4/7, before the idle checklist); afterwards 0.4–2.1 min on 9 measured edges. Measure both lags per critical-path edge in every retro.
- Team-lead overhead: 1.8 min from spawn to first engineer with a pre-written sheet (plan-web), 50 s (hardening); teams used 29/75 and 34/75 min; engineer active runs 1.5–12.4 min on 10–20-min boxes; a fix round is 2–9 min (P1's OPFS/bfcache fix 8.6 min, 46 tool uses, was the longest critical-path segment of step 7).
- Review latency inside a team: one review after the last task → engineers waited median 10 min (P3 18, T3 10, P5 10, P4 8.5, T4 4) for their fix round. Rolling review is the step-5 experiment.
- Concurrency: peak ≈ 12 live agents (2 team-leads + 6 nested + 4–5 Lead streams) at 23:34–23:45 without a rate-limit kill; S1 had died at 6 with 30–45-min research agents.
- Design-note slips that reuse the wrong shared schema (mcp §3 `EntityName` for `Label`) survive freezing because nobody greps the shared barrel at design time; architect.md Output 2 now requires the grep. Charter scope gaps (P6 sign-in) came from not reading the Log's "→ step 7" forward references; architect.md Output 4 now requires that grep.

**Why:** retro arithmetic and "did the rule reach the agent" judgements were wrong three times before (S2-T3 timing, S6 researcher spawn, step 4/7 remembered times) for lack of these facts.
